# 新知识卡：讲 → 例 → 测（v0.3，2026-11-08）

> 起因：用户指出「遇到新知识应该是先介绍清楚概念，再展示实际应用，最后才发题；用户不会怎么做题，做对了也是懵的」。
> 这推翻了原来"卡面先给问题、先猜再答"的统一设计——那个设计对**复习**成立，对**第一次见**是反的。

---

## 1. 一句话

**第一次见 = 教学卡（不测）；再次见 = 测验卡（先问）。**
同一张卡有两个模板，由"这个概念在他脑子里处于什么状态"决定渲染哪个。

---

## 2. 概念状态机

```
未学 unknown ──首次弹出（讲）──▶ 已讲 taught
                                   │
                        下次重逢 / 复习位
                                   ▼
                              练习中 practicing ──答对两次(不同题型)──▶ 已会 known
                                   │
                                答错/说没懂
                                   ▼
                              shaky（换说法再讲一遍，不降级）
```

| 状态 | 触发什么 | 卡片模板 |
|---|---|---|
| unknown | 首次遇到 | **teach**（只讲，不问） |
| taught | 之后重逢 | quiz（第一题：识别型） |
| practicing | 复习位 | 识别 → 因果 → 应用，逐级 |
| known | 不再主动弹 | 只在"重逢"时提一句 |

---

## 3. 教学卡（teach）的结构

顺序固定，**不许一上来给题**：

1. **它是什么**（≤40 字，一句人话，先不用术语）
2. **生活比喻**（≤50 字）
3. **一张图**（证明一个关系）
4. **你项目里的实际应用**（≤80 字）：agent 当时具体干了什么、结果怎样
   - 右上角固定「跳回这段对话」：session + turn + 原文一句
5. **一句所以**：以后看到 X，先想到 Y
6. 底部：`看懂了` / `再举个例` / `这个我会`

**没有选择题。** 第一次的任务只有一个：看懂。

---

## 4. 测验卡（quiz）的梯度

只在 `taught` 之后出现，且第一题永远是最轻的：

| 顺序 | 题型 | 例子 | 目的 |
|---|---|---|---|
| 1 | **识别** | 这三行里，哪一行在做「重试」？ | 建立对应，不需要推理 |
| 2 | **因果** | 为什么删掉这行就不重试了？ | 建立机制 |
| 3 | **应用** | 换个场景，你会先看哪里？ | 迁移 |

**答对也要解释一句"为什么对"**——不然就是"做对了也是懵的"。反馈模板：
> 对。你选的是第二行——因为 `for` 把请求包起来了，失败才会再走一次。

---

## 5. 掌握度怎么算（配合判定"没学过"）

| 事件 | 变化 |
|---|---|
| 首次讲解（taught） | +0.20 |
| 识别题答对 | +0.15 |
| 因果题答对 | +0.25 |
| 应用题答对 | +0.30 |
| 任意题答错 | −0.15，状态回 practicing |
| 他主动用这个词（对话里） | +0.20 |
| 点「这个我会」 | +0.40（答错可回退） |
| 7 天没碰 | ×0.9 |

**判定"已会"：S ≥ 0.65 且至少答对过 2 次不同题型。** 只答对一次不算——可能是蒙的。

---

## 6. 工作流卡（单独一类，按用户要求）

- 不进测验、不进复习位；
- 结构：**3 个决策点 + 每一步的取舍 + 一张流程图**；
- 检索方式：下次做同类任务时按"动作序列相似度"匹配，而不是概念匹配；
- 触发时机：规划阶段（还没动手时）提示一次，或者收口后讲"这次为什么顺"。

---

## 7. 例子按需生成（已定，2026-11-08）

教学卡不预生成很多例子，**按需调模型**：

| 按钮 | 调不调模型 | 生成什么 |
|---|---|---|
| 看懂了 | 不调 | 记一次讲解，进 taught |
| 再举个例 | **调** | 同类、另一个角度的例子（换场景，不升难度） |
| 太浅了 | **调** | 同类但**更进阶**的例子（更深机制/更多约束/更接近边界） |
| 这个我会 | 不调 | 标已会（答错可回退） |

**进阶怎么定义**（写进 prompt 的三个方向，任选其一）：
1. 加约束：原来一句话能解决，现在多一个限制条件；
2. 换边界：把例子推到"什么时候不成立"；
3. 跨场景：同一机制换到另一个项目里。

**生成规则**：
- 例子存进 `card.examples[]`，带 `level`（0 普通 / 1 进阶）和 `angle`；已生成的例子连同原卡一起喂给模型，明确要求"不要重复已有角度"；
- 单卡最多存 4 个例子，超了替换最早的非进阶例；
- 每次调用 ≤2k tokens、30 秒超时；失败就显示"这次没生成出来"，不重试三遍；
- 每天这类调用**全局上限 20 次**（和实时成卡共用一个预算池）。

## 8. 工作流卡：讲场景，不举例（已定）

工作流教的是一种**解决问题的思维**，所以卡片上放的是**常用场景清单**，不是具体案例：

```
这张卡：改动会牵动多处时，先侦察再动手
  决策点 1  先定"什么算对"，还是先动手？
  决策点 2  只读侦察到什么程度才停？
  决策点 3  改一处还是改一批？

  常用场景（点开任一场景 → 调模型生成该场景下的实例）
   · 跨平台适配（Mac 跑得通，Windows 报错）
   · 改动会牵动多个文件
   · 需求反复变更
   · 第三方服务不稳定
   · 数据迁移/格式转换
```

- **默认只给场景名 + 一句"这种场景长什么样"**，不举具体例子；
- 点某个场景 → **调模型生成一个该场景下的实际例子**（2k tokens），存进 `card.scenarios[].example`，同场景不重复生成；
- 场景清单由模型在生成工作流卡时给出（3–6 个），要求是"用户能用来定位自己当前处境的场景"，不是技术分类。

## 9. 实现顺序（下一步）

1. 概念状态机 + 数据表（`concept_state`：state / S / 答对次数 / 最后接触时间）；
2. 卡片模板分流：`unknown → teach`，`taught/practicing → quiz`；
3. 例子按需生成接口（`POST /api/card/example`）+ 面板按钮；
4. 工作流卡的场景清单与"点场景生成例子"；
5. 接进旁听面板（实时弹的是 teach 卡）。
