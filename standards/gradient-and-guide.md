# 梯度系统 & 知识点引导系统（设计草案 v0.1）

> 目标：从「上下文 ↔ 卡片一对一」升级成「**顺着知识网走**」——难度一档一档往上、知识一点带一片。
> 本文只写思路，不实装。

---

## 一、梯度系统：难度是「问句的形态」，不是话题

同一个概念，问法可以从「这是什么」一直到「换个项目还能不能用」。所以难度不挂在话题上，挂在**问句需要多少推理**上，分五档：

| 档 | 问句 | 卡面形态 | 题型 |
|---|---|---|---|
| **G0 认得** | 这是什么？ | 教学卡：命名 + 一句话 | 识别（三选一） |
| **G1 看懂** | 这行/这步在干嘛？ | 教学卡：意图 → 代码行 | 对应（哪一行） |
| **G2 讲清** | 为什么会这样？ | 因果卡 | 因果（为什么） |
| **G3 判断** | 什么时候不成立/该选哪个？ | 边界卡 + 对比卡 | 边界（例外）、选择（取舍） |
| **G4 迁移** | 换个项目/场景还能用吗？ | 跨项目变式 | 迁移（先看哪） |

### 怎么定一张卡在哪一档

- **概念底档**：每个概念有一个「最低从哪档开始」（新概念默认 G0，机制类往往 G2 起）。
- **卡档**：生成时打标（模型给候选 + 规则校验），一张概念可以有 G0–G4 多张卡。
- **判定档**：看题的类型，不看内容长短。

### 怎么升档（只升一档，不跳）

- 当前档「答对 2 次不同题型」→ 才允许升下一档；
- 同一概念**一周最多升一档**（防突击）；
- 升档后第一次仍是教学卡，不是直接考；
- 用户点「太浅了」＝手动 +1 档；点「没懂」＝当档重讲，不降档；
- 连续两次答错 → 回退一档，但保留已通过的记录。

### 内容怎么随档变

- G0/G1：只讲，不给题（第一次绝不考）；
- G2：讲 + 因果题；
- G3：加「什么时候不成立」的边界题，和容易混淆的概念对比；
- G4：换项目、换场景，考「先看哪里」。

## 二、知识点引导系统：触类旁通，不是相关推荐

核心区别：**推荐是“你可能还喜欢”，引导是“你下一步该学这个，因为……”**。每条引导必须带理由，且能落到一张卡上。

### 1. 三个发散方向（来自概念图的边）

| 方向 | 边 | 什么时候推 | 例子 |
|---|---|---|---|
| **往前** | 前置（prereq） | 当前概念学不动，或前置还没会 | 学「状态副本」前先补「会话投影」 |
| **往深** | 因果（cause） | 已经看懂“是什么”，该问“为什么” | 端口回退 → 为什么 bind 能试探占用 |
| **往反** | 对比（contrast） | 容易混淆的两个概念 | 布局约束 vs 页面与服务 |
| **往宽** | 同源（same） | 同一机制在别的项目出现过 | 换行符 → 跨平台适配里的同类坑 |

### 2. 什么时候推（三个入口，先做一个）

1. **卡后一行**（最轻）：讲完一张卡，底部一行「顺藤摸瓜：X（因为它是这条的前置）」；点开才生成，不点不消耗。
2. **会话收口**：这一轮干完，给一条 3 步路径「你在这 → 下一步 → 再下一步」。
3. **每周地图**：在概念图上标出「你碰过但没学」的缺口，一次最多 3 个。

> 建议先做 ①，它最不打扰，也最容易验证有没有用。

### 3. 推谁：一个排序公式

```
引导分 = 0.35 缺口程度（遇到过几次但还没会）
       + 0.25 前置满足度（它的前置都会了才推它）
       + 0.20 情境相关（最近 7 天在你的项目/会话里出现过）
       + 0.10 图上距离（1 跳优先，2 跳降权）
       + 0.10 新鲜度（7 天内没推过）
```

- **只推 1 个**，不推列表；
- 用户忽略 3 次 → 该方向降权；
- 前置没满足的，直接推前置，不推目标（“先补这个”）。

### 4. 主动发散：系统自己找，不等你问

三个“主动”：

1. **跨项目同源**：这个概念在别的项目出现过 → “同一个坑，你在另一个项目也踩过”；
2. **缺口提醒**：同一概念出现 ≥3 次仍 unknown → “你反复遇到它，但还没学过”；
3. **前置拦截**：你想学的东西前置没会 → 先给前置卡，而不是硬讲。

### 5. 引导的形态：不是弹窗，是“一行 + 点开”

- 默认只在旁听面板/卡片底部显示一行；
- 点开才生成内容（省 token、也不剧透）；
- 每天最多 1 条“顺藤摸瓜”、每周 1 次路径建议；
- 不打断当前任务，不抢焦点。

## 三、两个系统怎么配合

```
遇到知识点 → 判它现在在哪一档 → 给对应档的卡（梯度）
                     ↓
              讲完后看图上邻居 → 推 1 个下一步（引导）
                     ↓
              下一次遇到同类 → 档位 +1，或换发散方向
```

- **梯度管“多深”**，引导管“多宽”；
- 两个都用同一套概念状态，不另起炉灶；
- 引导推来的概念，第一次仍然是 G0 教学卡，不直接考。

## 四、数据模型要加的东西

| 表/字段 | 作用 |
|---|---|
| `concept.rung_floor` | 这个概念最低从哪一档开始 |
| `concept_state.rung` | 当前学到第几档（不是单一 S） |
| `concept_state.pass_json` | 每档答对过的题型 |
| `concept_edge.weight` | 边的强度，用于排序 |
| `exposure.jsonl` | 概念“出现过但没学”的记录（缺口来源） |
| `guide_log` | 推过什么、点没点、忽略几次 |

## 五、防跑偏的几条

1. 引导必须给理由（前置/因果/对比/同源/缺口），不给理由的就是推荐，不做；
2. 一次只推 1 个，不做“相关阅读”列表；
3. 推的东西必须能落到卡；落不到的只记缺口，不打扰；
4. 前置没会，不推目标；
5. 用户忽略 3 次，降权；忽略 10 次，停推该方向；
6. 每周最多 1 次“体系建议”，其余都是卡后一行。

---

## 六、需要你拍板的 5 个问题

1. **难度五档**（认得 → 看懂 → 讲清 → 判断 → 迁移）你认可吗？还是想更粗（基础/进阶/硬核三档）？
2. **升档**只由行为决定（答对两次不同题型 + 一周最多一档），另给你「太浅了/没懂」手动调一档——可以吗？
3. **引导入口**先做哪个：卡后一行 / 会话收口 / 每周地图？（我建议卡后一行）
4. **发散半径**：只推 1 跳邻居，还是允许 2 跳路径（A→B→C）？
5. **缺口提醒**要不要主动提（你反复遇到但没学的概念）？提的话一天最多几次？
