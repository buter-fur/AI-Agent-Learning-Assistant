# 卡片库 ↔ 知识库 · 定位与入库规则 v0.1

> 状态：**2026-11-14 用户拍板**：卡片上限 50 张，**只算未学的卡**；学会的（concept_state=known）默认隐藏且不占名额；复习答错会自动回到卡片流，可轮训、不是一次性。50 张未学卡＝「没学会的小知识库快速命中」，其余知识由知识库补。
> 背景：现在两边都在存知识，功能有重叠；但先说一个好消息——**内容并不重复**。

---

## 一、先看数字（2026-11-13 实测）

| 项 | 数量 |
|---|---|
| 知识库条目 | 每条带引文、来源锚点、标签；一部分由卡片导出，一部分是独立问答/经验 |
| 卡片 | 一组知识卡 + 工作流卡；有讲例测、题、档位、掌握度 |
| 概念 | 18 个，概念之间的边 12 条 |
| 知识库实际用到的标签 | 56 个（其中 50 个出现 ≥2 次） |
| 重复检查 | 标题 + 正文前 80 字的相似度，**没有任何一对 ≥0.5** |

**结论：不是"一份知识存了两遍"，而是"两个东西都在做知识，但没有分工"。**

- 卡片库：有讲例测、有题、有档位、有掌握度——**但只覆盖知识库的一部分**；
- 知识库：有引文、来源锚点、标签——**但只负责检索，不负责教**；
- 实时链路：先查卡片，查不到再查知识库——**两边打分口径不同，同一件事会两次出现**。

---

## 二、建议的定位（一句话）

- **知识库 = 原料库 / 检索层**：一条知识 = 一个可核验的小点，全量收，负责"查得到"。
- **卡片库 = 教学层**：从知识库里挑"值得教、能出题、有边界"的，负责"学得会"。

用你的项目打比方：知识库是**食材仓库**，卡片是**做好的菜**。仓库要全，菜要精；不能拿菜当仓库用。

---

## 三、入库规则

### 3.1 进知识库（KB）——宽进，但有硬门槛

一条知识必须同时有 6 样东西：

| 字段 | 要求 | 不合格怎么办 |
|---|---|---|
| 标题 | ≤18 字，能看出"对象 + 动作 + 结果" | 退回重写，不入库 |
| 一句话 | 6–40 字，恰好 1 句，不许省略号 | 退回重写 |
| 正文 | 80–400 字，人话 | 退回 |
| 引文 | **必须在会话原文逐字命中** | 直接拒收（防编造） |
| 来源 | `项目 · session=…#seq=…` | 缺 session/seq 标 B 级，仅展示不参与定位 |
| 标签 | 2–5 个，来自 59 词表；没有合适的才新增 | 先用本地模型从词表里选（已接） |

- 相似度 ≥0.85 的条目合并（当前条目里没有这种重复）；
- 每条最多归一个"主项目"，标签里可以跨项目；
- KB 不承担教学：不写比喻、不出题、不记掌握度。

### 3.2 进卡片库——窄进，四道闸

从 KB 里挑，**不是另外写一份**：

| 闸 | 条件 | 不满足 |
|---|---|---|
| 1. 可迁移 | 至少 1 个跨项目证据，或属于判断/机制类通用规律 | 留在 KB，不做卡 |
| 2. 有边界 | 能写清"什么时候不成立/该选哪个" | 留在 KB |
| 3. 能出题 | 至少能出 2 道不同题型（识别/因果/应用/对比/推演） | 留在 KB |
| 4. 引文 A 级 | 引文能逐字命中原文 | 留在 KB |

- **一条 KB 最多对应 1 张卡**（`card.kb_id` 外键）；
- 卡片里的知识正文**引用 KB 版本**，不复制一份再各改各的；
- 卡片只新增教学字段：比喻、图、题、边界、档位、掌握度；
- 编辑方向单向：**KB → 卡片**。改知识改 KB，卡片跟着更新；卡片里只改教法。

### 3.3 实时链路怎么用两层

```
现场信号
  → 卡片命中（<100ms）：直接弹卡；同时后台拿 card.kb_id 查 KB，只找「卡片没讲的角度」
  → 卡片没命中：查 KB（50–150ms）
       ≥0.60 直接弹知识卡
       0.35–0.60 本地 27B 判（已接）
       <0.35 丢
```

关键：**同一条知识命中时，不再"卡片一次、知识库一次"弹两遍**。卡片命中后，KB 只补卡片没讲的部分（角标），不重复弹原文。

### 3.4 展示与去重

- KB 条目加 `covered_by_card`：被卡片覆盖的条目不进"新卡推荐"，但在标签网络/语义地图里仍然可见（你要查得到）；
- 卡片流只展示卡片，不展示原始 KB 条目；
- 检索/标签/地图展示 KB 全量，但被覆盖的条目标灰并注明"已有卡片"。

## 四、迁移怎么做（4 步，不动现有内容）

1. **加字段**：`card` 表加 `kb_id TEXT`（空表示还没对应）；
2. **对上号**：卡片的 id 与 KB 的 `kb_card-*` 一一对应，写进 `kb_id`；
3. **导出脚本改造**：`export-kb-doc.mjs` 对已有 `kb_id` 的卡片不再重复生成正文，只在 KB 里保留原条目并标 `covered_by_card`；
4. **检索去重**：`whisper.mjs` 命中卡片后按 `kb_id` 排除同一条 KB，避免双弹。

这四步都是加字段/改判断，不删数据；迁移前先备份 `cards.db`。

## 五、需要你拍板

1. **卡片上限**：建议先定 50 张（现在 18）。到上限不是不做了，而是"新卡进候选池，先淘汰价值最低的"。同意这个上限吗，还是想按项目分配（比如每项目最多 8 张）？
2. **冲突以谁为准**：卡片和 KB 讲法不一致时，建议**以 KB 为准**（KB 有引文），卡片改教法不改事实。同意吗？
3. **卡片流是否隐藏被覆盖的 KB 条目**：建议隐藏（只在知识地图和标签里可查）。还是你想在卡片流里也能看到"原始条目"入口？
